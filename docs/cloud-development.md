# 微信云开发接入

项目默认使用本地体验数据。完成以下配置后，两台微信设备会共享同一个双人菜单册。

## 1. 填写小程序 AppID

在 `src/manifest.json` 的 `mp-weixin.appid` 中填写微信公众平台的小程序 AppID。编译后的 `project.config.json` 会自动使用该 AppID。

## 2. 创建云环境

在微信开发者工具中开通云开发，创建一个环境，然后复制 `.env.example` 为 `.env.local`：

```ini
VITE_USE_CLOUD=true
VITE_CLOUD_ENV=你的云环境ID
```

## 3. 创建数据库集合

创建以下集合：

- `kitchens`
- `menus`

两个集合的权限都设为“仅云函数可读写”。客户端所有数据操作都通过 `two-person-menu-api` 云函数完成，不能把集合开放为“所有用户可读写”。

为 `menus` 创建组合索引：

1. `cookedAt`：降序
2. `createdAt`：降序

## 4. 部署云函数

微信开发者工具应导入最终编译目录：

```text
/Users/chenmingyu/code/two-person-menu/dist/dev/mp-weixin
```

每次编译都会自动把源码中的云函数同步到该目录，并更新产物内的 `project.config.json`。

在开发者工具中找到 `cloudfunctions/two-person-menu-api`，选择“上传并部署：云端安装依赖”。云函数使用 `wx-server-sdk@4.0.2`。

## 5. 双人绑定规则

- 第一位打开云端版小程序的微信用户会自动占用第一个位置。
- 第二位打开的微信用户会自动占用第二个位置。
- 第三位微信用户会收到“这个菜单册已经绑定两个人”的提示，无法读取或修改菜单。
- 两名已绑定成员都能查看、新增、编辑和删除全部菜单。

因此，首次部署后应只把体验二维码发送给确定的另一位成员。若误绑定，需要在云数据库 `kitchens` 集合中清空对应成员的 `openid`，再让正确成员进入。

## 6. 真机验收

1. 第一台手机进入，修改第一位的名字和头像。
2. 第二台手机进入，修改第二位的名字和头像。
3. 第一台新增一道菜，第二台重新进入首页确认可见。
4. 第二台编辑该菜，第一台重新进入详情确认已更新。
5. 使用第三个微信账号进入，确认被拒绝。
6. 删除一道菜，确认数据库记录和云存储图片均被删除。
